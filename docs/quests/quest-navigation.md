# 장사 NPC 배치와 퀘스트 목적지 안내

장사 주민 30명을 배치했다. 의뢰 원고에 등장하는 14명과 생활 주민 16명이다. 길 가운데를 피하고 가게 앞·마당·노점 옆·골목 가장자리에 두었다. 정확한 좌표와 역할은 `godot/assets/maps/changsha/layout.json`의 `residents`에 저장한다. `road_centers`는 주민 배치를 피하는 띠이며 통행 금지 영역이 아니다. 주민의 발 위치와 몸 전체가 장애물에 겹치지 않고 시작점에서 접근 가능한지 검사한다.

| 의뢰 관련 인물 | 배치 장소 |
|---|---|
| 포목상 | 항구 앞 포목 노점 |
| 점소이 | 객잔 앞마당 |
| 목수 | 공방 작업대 옆 |
| 채소 장수 | 시장 노점 옆 |
| 잡화상 | 잡화 노점 옆 |
| 행상인 | 객잔 옆 처마 |
| 우물가 노파 | 주거지 우물 옆 |
| 하역 인부 | 나루 하역장 가장자리 |
| 창고 보조 | 창고 출입구 옆 |
| 창고지기 | 창고 마당 |
| 노농 | 동문 밖 농가 옆 |
| 농부 | 농가·물길 옆 |
| 골목의 노인 | 주거지 처마 앞 |
| 젊은 공방 일꾼 | 공방 작업 마당 가장자리 |

현재는 기존 공용 도트 주민을 재사용한다. 고유 외모·대사 상호작용·전투 능력치를 새로 확정하지 않는다.

## 안내 표시

- 금색 화살표: 플레이어. 청록색 점: 주민.
- 주황색 마름모: 추적하는 퀘스트의 목적지.
- 목적지가 미니맵 밖에 있으면 가장자리의 주황색 방향 화살표로 전환한다. 미니맵은 북쪽이 위이며 N 표기를 제공한다.
- 하단에 현재 목표 설명을 표시한다. 추적 대상이 없으면 안내 표시를 숨긴다.
- NPC 목표는 고정 좌표 대신 실제 NPC 위치를 따라간다. 수집 지점이 여러 곳이면 남은 목표 중 가까운 곳을 안내한다. 해당 단계의 모든 목표가 달성되었다고 전달받으면 보고 NPC를 안내한다.
- TAB 전체 지도에도 주민과 추적 목적지를 표시한다. 방향 안내이며 자동 이동이나 장애물 우회 경로는 아니다.

## 구현 연결과 현재 범위

`godot/scripts/quest_navigation.gd`는 명시적으로 전달받은 퀘스트·단계·달성 목표 목록을 안내한다. `godot/data/changsha_navigation.json`에 9개 의뢰의 단계별 목적지를 저장했다. 현장 조사·수집 좌표는 기능 연결을 위한 접근 가능한 후보 지점이며 아이템이나 조사 오브젝트를 생성하지 않는다.

```gdscript
quest_navigation.track("changsha_cloth", "deliver")
# 여러 수집 목표 중 이미 달성한 목표를 제외한다.
quest_navigation.track("changsha_pages", "collect", ["page_1", "page_2"])
quest_navigation.clear()
```

퀘스트 수락·진행 판정·대화·보상·NPC 느낌표/물음표는 아직 별도 구현 대상이다. 탐방 시작 시 의뢰를 임의 자동 수락하지 않는다. 향후 퀘스트 상태 관리가 위 API를 호출한다. 옷감 → 식기 → 농기구만 연계하고 다른 여섯 의뢰는 독립이라는 기획을 유지한다.

실제 Godot 캡처에서는 옷감 전달 단계를 명시적으로 추적해 안내 동작을 보여 준다. 게임 플레이 중 퀘스트가 수락된 결과를 촬영한 것은 아니다.

![미니맵 밖 목적지 안내](../../godot/screenshots/changsha-navigation-outside.png)
![미니맵 안 목적지 안내](../../godot/screenshots/changsha-navigation-inside.png)

검증: `godot --headless --audio-driver Dummy --path godot --script res://tests/quest_navigation.gd`. 9개 의뢰의 모든 단계 목적지 접근, 14명 배치, 길 중앙 회피, 8방향 화살표, 내부 목표 표시, 실제 NPC 위치 추적, 달성 목표 제외, 보고 목적지 전환과 초기화를 검사한다.

최신 변경: [1장 도입](../story/chapter-01-intro.md)에서 첫 옷감 의뢰를 실제 자동 수락하고 이 안내 API에 연결한다. 나머지 의뢰의 진행 기능과 수집 오브젝트는 여전히 후속 작업이다.
