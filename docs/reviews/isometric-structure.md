# 장사 시험 · 데이터·상태·입력 구조 점검

기존 `changsha.tscn`과 의뢰2개·웅력환 구매1종·8×6 실내의 구조를 화면 없는 검사로 점검했다. 미술·맵·NPC·상품·의뢰·UI 디자인·영상·캡처를 추가하지 않았다. 혼잡도/성능 시험은 재개하지 않았다. 본게임 소스·경제/보상 정의·저장 시스템은 수정하지 않았다.

## 재현한 문제와 최소 수정

| 재현 조건 | 원인 | 수정 |
| --- | --- | --- |
| 거래창을 두 번 연 뒤 닫기 | 두 번째 열기에서 이전 정지 상태를 true로 덮어써 정지가 남음 | 거래 세션이 열려 있으면 재진입 거절, 이전 정지 상태를 한 번만 보관 |
| 거래 중 늦은 일지 닫기, 일지 중 거래 닫기/닫힘 신호 반복 | 일지의 busy 판단이 거래까지 포함했고, 거래 닫힘 처리도 무조건 이전 상태를 적용 | 일지는 실제 표시 여부로 닫기 판단. 거래는 표시 여부와 세션 소유 여부로 한 번만 복원 |
| 일지 위로 거래를 다시 열기 | 거래 진입 경계에서 다른 창/전환/대화 여부를 검사하지 않음 | 같은 시험 안에서 일지·대화·전환 중 거래 진입 거절 |
| 중간 버튼으로 카메라 이동→일지에서 버튼 놓기→닫기 | 배경에서 버튼 해제를 받지 못해 drag가 남음 | 일지와 출입 전환 시작 때 drag를 해제. 원래 카메라 배율/추적 설정은 유지 |
| 메모리 시험 장면에서 항아리를 제거하고 해당 좌표에서 F | 조사 조건이 좌표만 확인해 실제 물건이 없어도 조사 가능 | 기존 두 의뢰에 table/urn ID 연결을 추가하고 활성 씬의 실제 노드 존재 여부를 검사 |
| 암전 도중 시험 씬 제거 | 소유 Tween이 종료되면 finished 신호가 발생하지 않아 대기 중 GDScriptFunctionState가 남음 | 출입 코드 안의 대기를 취소 가능하게 하고 씬 종료 때 깨워 연결을 해제. 프레임 대기에도 종료 확인 적용 |

정상 배치에서 항아리가 누락되어 있던 것은 아니다. 잘못된 장면/데이터를 넣는 음성 검사에서 발견한 구조적 연결 문제다. target_id 추가는 기존 의뢰 데이터의 작은 보강이며 좌표·문구·조건 수치·보상을 바꾸지 않는다.

수정 파일은 `iso_town_errands.gd`, `iso_town_shop.gd`, 공통 `iso_errand.gd`, `iso_passage.gd`, `town-quests.json`이다. 본게임 `city_service.gd`·`player_progress.gd`·`dialogue_history.gd`는 읽고 재사용했으며 수정하지 않았다. 원래 속도4.8·표시 크기·85% 배율·보행·물리 보간·배치/씬 파일과 미술은 유지한다.

## 데이터 검사

추가한 `tests/check_isometric_town_data.py`는 Python 표준 라이브러리만 사용한다. 원본 JSON/관련 코드 상수는 읽기만 하고, 오류 실험은 깊은 메모리 복사본에서 수행한다.

- 명시적 오브젝트·담장·NPC ID 중복과 생성되는 담장 조각 ID 충돌, 중복 JSON 키.
- 의뢰 제공자·화자·조사 대상, 담장 소속 공간과 공용 포장 인덱스 참조.
- 출입 씬/초상화/건물·인물 그림/상품 아이콘 파일 존재. 이번 출입은 기존 room.tscn으로 제한.
- 좌표·점유 크기·시작점·왕복 경로의 형식/유한값/맵 범위, 조사 좌표와 대상 점유 범위의 일치.
- 판매 상품 존재·필수 필드·양의 정수 가격·초기 지갑 형식. 실행 중 초기 수량/지갑도 Godot에서 확인.
- 31개 오류 사례: 중복 ID, 없는 참조/파일, 필수값 누락, 잘못된 자료형, 범위 밖/0크기/NaN 좌표, 음수·0·소수·문자열/NaN 가격, 음수 지갑 등.

행상은 코드에서 생성되고 의뢰 상태 키도 코드에 있다. 정적 검사만으로 생성 결과를 단정하지 않고 Godot 검사에서 실제 NPC/오브젝트 ID, 제공자/화자 연결, 정의와 상태 키를 대조했다. 이 검사는 현재 시험의 작은 구조 전용이며 임의 JSON 전체의 범용 스키마 검사기는 아니다. 그림의 실제 입구 방향·그림자·픽셀 겹침은 이번 정적 검사 대상이 아니다.

## 상태·입력 검사와 재사용

새 `isometric_town_structure.gd`는 기존 `isometric_town.gd`의 생성·F/Q/H/선택 입력·대화 마무리·실내 출입 도우미를 상속한다. 기존 전체 순환 이동을 새 검사에 복제하지 않고, 잘못된 순서·중복 호출·정지 복원·중도 제거에 집중했다.

- 진행 데이터 스냅샷: 의뢰별 상태/완료 횟수·추적·돈·소지품·능력치. 거절된 요청 전후가 같음을 확인했다. 오류 문구/입력 잠금 같은 일시적 UI 값은 진행 데이터와 구분한다.
- 실제 F 대화의 마지막 처리를 다시 호출해도 단계/보상이 중복되지 않는다. 수락/조사/보고의 상태 조건도 따로 검사했다.
- 기존 장사 통합 검사를 재실행해 두 완료 순서·추적 해제·거래 재진입·실내 왕복·돈/물품 유지·무보상 상태를 확인했다.
- 공통 코드를 수정했으므로 기존 `isometric_passage.gd`와 `isometric_errand.gd`를 재실행했다. 외부 NPC 경로/카메라 복원과 F/W 유지 보호도 포함한다.
- 새 상태 검사79항목, Python 정적 검사3개 메서드(메모리 오류31사례 포함), 기존 회귀3개 모두 PASS. 임시 최소 암전 종료 재현에서도 변경 전 누수 경고1건이 변경 후 사라졌다.

이번에 수정한 공통 일지/출입 코드는12×12 비교 씬에서 사용하지 않는다. 해당 씬은 별도 재실행하지 않고 파일 보존을 확인했다. 관련20×16 의뢰/출입 검사는 재실행했다. 모든 Godot 검사는 실제 플레이와 분리한 XDG 사용자 폴더에서 headless/fixed-fps60으로 실행했다. 이 값은 기능 검사용이며 실제 FPS 측정이 아니다.

## 입력 허용 기준

| 상태 | 이동 | F | Q | 허용되는 주요 조작/복원 |
| --- | --- | --- | --- | --- |
| 탐험 | 허용 | 접근 가능한 안내 대상1개 | 일지 열기 | 기존 선택/카메라 조작 |
| 대화 | 도원/상대 정지 | 새 입력으로 다음 대사, 선택은1/2 | 차단 | H 기록. 다른 NPC 왕복 유지 |
| 대화 기록 | 차단 | 진행 차단 | 차단 | H/ESC로 대화 복귀, 진행 줄 유지 |
| Q 일지 | 차단 | 배경 행동 차단 | 닫기 | 마우스로 의뢰 선택/추적, ESC 닫기 |
| 거래 | 차단 | 배경 행동 차단 | 차단 | 마우스로 구매, ESC/돌아가기 |
| 출입 암전 | 차단 | 중복 출입 차단 | 차단 | 전환만 진행, 중도 제거 시 대기 정리 |
| 창 닫기/복귀 직후 | 눌려 있던 이동은 중립 확인까지 차단 | 유지된 F는 해제 필요 | 탐험 상태에서 재사용 | 새로운 입력으로 이동/상호작용 재개 |

표의 동작은 자동 입력과 상태/위치 값으로 확인했다. 이번에는 새 화면 캡처를 만들지 않아 픽셀 수준의 표시·Windows 포커스/IME/실제 장치의 키 이벤트는 확인하지 않았다. 창을 닫을 때 무조건 정지를 해제하지 않고, 원래 다른 이유로 정지돼 있었다면 그 상태를 유지함을 검사했다.

## 확인한 원칙과 남은 과제

이번 시험에서 확인한 것은 ID/참조 검사, 독립된 의뢰 상태와 중복 처리 방지, 상품1종의 구매 원자성, 창 소유 상태에 따른 한 번의 정지 복원, 씬 수명에 맞춘 비동기 대기 정리다. 이를 본게임 전체가 준수한다고 판정하지 않는다. 본게임 보상/저장과 잘못된 외부 저장 데이터, 모든 상품/서비스 조합은 이번 범위 밖이다.

다음 저비용 우선순위는 **의뢰 정의와 초기 상태 키의 중복 관리 정리**다. 현재 정의 JSON과 phases/completions의 두 ID를 따로 관리하며, 이번 검사로 일치를 확인했지만 세 번째 의뢰를 추가할 때 누락 위험이 있다. 정의에서 초기 상태를 만들도록 작은 정리를 검토할 수 있다. 상인·상품·초기 금액의 코드 상수도 추후 콘텐츠 정의로 모으는 것을 추천한다. 이번에는 새 상태 프레임워크나 전체 데이터 형식 개편을 하지 않았다.

검사를 콘텐츠 추가 때 다시 실행하는 것은 추천 기준이다. 자동 CI나 본게임 전체에 대한 강제 규칙을 새로 적용한 것은 아니다. 혼잡도 시험 프롬프트는 계속 보류한다.

## 실행·업데이트

```powershell
cd C:\Users\PC\murim-rpg
git pull --ff-only
```

플레이 확인: `C:\Users\PC\murim-rpg\godot\prototypes\isometric\changsha.tscn`
(`res://prototypes/isometric/changsha.tscn`)을 Godot에서 열어 F6. 원래 프로젝트는 `godot/project.godot`이며 F5는 본게임이다.

자동 검사 파일:
- `godot/tests/check_isometric_town_data.py`
- `godot/tests/isometric_town_structure.gd`

Python/Godot 실행 파일이 PATH에 등록된 환경에서 저장소 루트 기준:

```powershell
python .\godot\tests\check_isometric_town_data.py
godot --headless --fixed-fps 60 --path godot --script res://tests/isometric_town_structure.gd
```

Godot 검사에는 실제 플레이와 분리된 사용자 데이터 폴더를 사용한다. JSON 결과가 필요할 때만 마지막 명령 뒤에 `-- --out=<쓰기가능한경로>`를 붙인다. 기본 실행은 진행 상태를 파일에 저장하지 않는다. 그림·영상·화면 캡처를 생성하는 명령은 없다.
