# 화면·조작 경험 개선 검토 — 2026-10-27

현재 코드와 저장된 실제 Godot 캡처를 검토한 제안이다. 게임 코드·수치·입력·이야기는 변경하지 않았다. 참고 작품은 알려진 UI/플레이 설계의 비교 대상으로, 이번 작업에서 해당 게임들을 직접 실행해 측정한 결과는 아니다. 이동·카메라 체감과 성능은 아래 실측 과정이 추가로 필요하다.

## 우선 적용 묶음

1. **공통 UI와 조작 일관성**: 선택/사용 불가/포커스 구분, 여백·서체·버튼 위계, ESC 한 단계 닫기/열기 키로 닫기/전체 키보드 탐색.
2. **I/K/거래 재구성**: 정보 카드와 장착 요약,4슬롯 직접 편성, 현재 슬롯 비교, 상태 기억, 구매 후 정비 연결.
3. **탐험 체감**: 대상 고정과 명시적 F 안내, 혼잡 표식 정리, 네 방향 보행/카메라 A/B 검토. 속도와 크기를 먼저 다시 바꾸지는 않는다.
4. **타이틀·저장·전투 가독성**: 최근 진행 이어하기, 저장 식별, 자신 행동/내기/방어 상태를 빠르게 파악하는 전투 패널.
5. **환경 대응과 마감**: 전체 UI 배율/긴 한국어/창 크기, 최소 사양 계측, 효과음 믹스·환경음.

각 묶음은 같은 저장으로 전후 화면과 조작을 비교한 뒤 확정한다. 여러 창을 한 번에 바꿔 원인을 구별할 수 없게 하지 않는다.

## 검증 과제와 제안 기준

- 처음 온 플레이어가 최근 저장으로 이어서 시작하고 현재 위치/목표를 설명할 수 있는가.
- NPC가 가까이2~3명 있을 때 원한 상대에게 F로 말할 수 있는가. 대상이 흔들리거나 벽 너머로 잡히지 않는가.
- 무기 구매→장착→무공 편성을 별도 설명 없이 수행하는가. 편성은 무공/슬롯 선택 후 적용까지3행동 이내를 목표로 한다.
- 현재 장비로 못 쓰는 무공의 원인을5초 이내 설명하는가. 무공 소모와 매 턴 회복을 구분하는가.
- 메뉴를 닫고 열면 탭/선택/스크롤이 유지되는가. ESC는 가장 위 창만 닫는가. UI 조작이 필드 F/대화 넘김으로 새어 나가지 않는가.
- Q의 목표에서 해당 지도를 보고 다른 지역에서도 길을 찾을 수 있는가. 표식 의미를 색만으로 판단하지 않아도 되는가.
- 여러 저장 중 다른 분기의 시점을 찾을 수 있는가. 사망해도 기존 저장이 보존되는가.
- 최장 아이템명/긴 대사/무공30개/아이템50개와 빈 목록/품절/내기 부족/최대 글씨/다양한 창 크기를 시험한다. 아직 없는 콘텐츠는 검사용 데이터로만 채운다.
- 응답 목표 초안: 메뉴 입력 후 시각 반응100ms 이내, 일반 메뉴 전환150~250ms 이하. 탐험60fps 목표는 기준 PC를 정한 뒤 평균보다95/99백분위 프레임 시간과 순간 멈춤을 함께 측정한다. 현재 측정값이 아니다.
