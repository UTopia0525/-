# 건물 방향과 마당 경계 배치 규칙

사용자가 이전 해석을 정정한 최신 기준이다. 앞으로 건물을 새로 배치하거나 배치를 변경할 때 **실내 구현 여부와 관계없이** 적용한다.

1. **입구/건물 정면이 접근 도로·골목을 향하도록 건물 방향부터 결정한다.** 길을 등진 건물을 그대로 둔 채 담장에 구멍을 내거나 뒤편으로 새 길을 둘러 해결한 것으로 간주하지 않는다.
2. 카메라에서 보이는 면에 맞는 앞/옆/뒷면 그림을 사용한다. 필요한 방향의 그림이 없으면 추가 제작한다. 평면 회전/비균등 확대나 단순히 문을 뒷벽에 복제하는 방식으로 방향을 속이지 않는다.
3. 길 쪽 문이 카메라 반대편에 있으면 건물 뒷면이 보이는 것이 정상이다. 실제 문 위치는 해당 정면의 바닥 좌표로 등록하고 가려진 문을 후면에 억지로 그리지 않는다.
4. **담장은 건물에 딸린 마당/대지를 외부와 분리하는 경계 시설이다.** 소속 건물과 마당 영역을 지정하고 외곽 경계에 맞춰 연결한다. 구획과 무관한 외딴 담장이나 쓰임 없는 담장 조각을 두지 않는다.
5. 대문/출입구만 의도적으로 열고 나머지 경계는 이어 준다. 담장은 문 앞 공간/공공 보행로/건물 출입을 막지 않는다. 문기둥은 충돌하되 통로는 인물 발밑 크기와 여유 폭을 확보한다.
6. 민가에는 생활 마당, 창고에는 작업 마당처럼 용도에 맞는 공간을 둔다. 도로 → 마당 출입구 → 정면 문턱까지 실제로 걸어갈 수 있어야 한다.
7. 건물 바닥 점유/문턱/기단/지붕 가림을 구분한다. 그림·바닥·그림자와 충돌이 같은 방향/배치를 따르는지 플레이 카메라에서 확인한다.

## 독립 시험 구현

민가는 중앙 골목 쪽 정면을 유지하면서 왼쪽으로 옮겨 독립 마당을 확보했고 기존 대문을 해당 마당의 남쪽 출입구로 옮겼다. 오른쪽 창고는 정면을 중앙 골목 쪽으로 돌렸으며 카메라에는 새 `warehouse-back.png`의 뒷면이 보인다. 중앙 골목은 공공 통로로 남기고 두 마당은 각각 연결된 담장으로 분리했다. 이전에 만든 창고 뒤 우회 출입구는 제거했다.

| 데이터 | 역할 |
| --- | --- |
| 건물 `front`, 에셋 `front`/`view` | 실제 정면 방향과 카메라에서 보이는 면 |
| `entrance.threshold` / `facing` / `road_anchor` | 문턱, 정면 방향, 향해야 할 도로 지점 |
| `entrance.visibility` | 원화의 문이 보이는지, 뒷면 그림에 가려지는지 |
| `entrance.approach` / `apron` / `path` | 문 앞 접근 지점·빈 공간·공용 길에서 오는 경로 |
| `plots` | 각 건물에 속하는 마당/대지의 영역과 허용 출입구 |
| 건물/담장/대문의 `plot` | 소속 마당 ID |
| `entrance.interior` | 실내 미구현은 `null`; 방향/마당/접근 요건은 유지 |

`iso_access_rules.gd`는 건물과 에셋의 정면 일치, 입구가 도로를 향함, 실제 그림의 문 위치 또는 가려진 정면 위치, 문 앞 공간/이동 충돌, 담장 소속/경계 정합, 선언한 출입구 이외의 경계 끊김을 검사한다. G키에서 마당 외곽과 접근 경로를 본다. 실제 입력 이동 검사와 방향/경계 오류의 실패 검사도 제공한다.

이 자동 검사는 현재 작은 직사각형 마당 시험용이다. 본게임 도시 전체를 소급 변경/검사하지 않았으며 비정형 대지·공유 마당·다층/계단 등은 해당 콘텐츠를 만들 때 별도 모델이 필요하다.
