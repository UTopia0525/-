# 건물 배치와 외부 진입 동선

사용자 승인 규칙이다. 앞으로 건물을 새로 배치하거나 배치를 변경할 때 적용한다. **실내를 구현하지 않는 건물도 예외가 아니다.** 내부 진입 기능과 외부에서 문까지 다가갈 수 있는 구조를 구분한다.

1. 그림의 실제 문 위치와 방향부터 확인한다. 건물 중심이나 충돌 사각형 모서리를 문으로 추정하지 않는다.
2. 공용 길 → 골목/마당/대문 → 문 앞 공간 → 문턱의 연결을 설계한다. 모든 문이 큰길을 직접 향할 필요는 없지만 실제로 연결된 진입 경로가 있어야 한다.
3. 용도에 맞는 전면 공간을 둔다. 민가는 작은 마당, 창고는 짐을 내릴 공간, 점포는 진열과 보행을 분리한 앞자리를 확보한다.
4. 문기둥·담장·소품·다른 건물이 길과 문을 막지 않게 한다. 발밑 충돌 크기와 여유 폭으로 검사하고 실제 인물로 걸어 본다.
5. 문 방향이 길과 맞지 않으면 건물 위치/적절한 방향의 원본 그림/연결 마당을 조정한다. 정면 그림을 평면 회전하거나 비균등 확대해 측면을 만들지 않는다.
6. 건물 바닥 점유, 문턱, 지붕/문 위 가림을 구분한다. 벽을 관통해 접근하거나 그림만 문인 막힌 통로를 만들지 않는다.
7. 주변 길과 마당의 재질·기단·접지 그림자를 연결하고 플레이 카메라에서 앞뒤 가림과 접근성을 함께 검토한다.

## 독립 아이소메트릭 시험의 데이터 예

`prototypes/isometric/assets/manifest.json`은 원본 그림 내부의 `door_pixel`을 지정한다. `layout.json`의 건물별 `entrance`에는 다음을 지정한다.

| 필드 | 의미 |
| --- | --- |
| `threshold` | 실제 그림의 문턱에 대응하는 논리 바닥 좌표 |
| `facing` | 문에서 바깥으로 향하는 논리 방향 |
| `approach` | 문 정면에 서서 접근하는 지점 |
| `apron` | 문턱과 접근 지점을 포함하는 비어 있는 앞마당 |
| `path` | 공용 길부터 접근 지점까지의 연속 경로 |
| `kind` | 작은 마당/하역 마당 등 공간의 용도 |
| `interior` | 실내가 없으면 `null`; 위 외부 접근 정보는 여전히 필수 |

`iso_access_rules.gd`는 그림의 문/등록 좌표 일치, 문 앞 방향, 마당 크기/장애물, 공용 길과 연결된 포장, 문턱까지 발밑 충돌 없는 이동을 검사한다. 시작과 G키에서 확인하며 테스트에서는 문 앞까지 실제 입력으로 걸어 간다. 문 정보 누락·뒤집힌 방향·잘못된 그림 기준점·담장으로 입구를 막는 실패 사례도 검사한다.

이 검사는 현재 작은 시험 씬의 직사각형 포장과 건물에 맞춘 구현이다. 모든 본게임 도시의 자동 검사로 연결하거나 기존 배치를 일괄 수정한 것은 아니다. 대규모 도시에는 열린 공간/통행 가능한 바닥 다각형, 계단·다층·문 종류와 지역별 충돌 규약을 연결하는 추가 작업이 필요하다.
