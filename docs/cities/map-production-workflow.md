# 새 맵·도시 제작 순서와 명령 프롬프트

2026-11-01 사용자 확정. [필드·도시 구성 원칙](field-layout-principles.md)을 실제 제작에 적용하는 절차다. 크레딧과 재작업을 줄이기 위해 **설계→대표 구역→전체 확장**을 별도 작업으로 나눈다. 아래 도시의 이름·지형·시설은 명령 예시이며 확정 콘텐츠가 아니다. 이 문서를 읽는 것만으로 어느 단계도 실행하지 않는다.

## 1. 역할과 공간 구조 설계

사용자가 도시 역할, 지형/외부 연결, 필요한 시설, 구현 범위, 유지할 기준을 제시한다. 빠진 조건은 기존 설정과 자료를 우선 확인한다. 제작자는 구역 간 관계와 사람/물자 동선, 도로, 부지, 입구, 작업 공간을 글·간단한 도식·배치 데이터로 정한다. 미술을 대량 제작하지 않는다.

설계 산출물은 구역 역할/인접 관계, 주요 동선, 건물 부지와 접근, 기존 에셋 활용 범위, 부족한 미술 목록, 대표 구역 선정, 예외/불확실성이다. 사용자에게 검토 체크리스트를 떠넘기지 않는다.

```text
새로운 강변 상업 도시의 맵을 설계해줘.

AGENTS.md와 docs/CLI_HANDOFF.md를 먼저 읽고,
docs/cities/field-layout-principles.md와
docs/cities/map-production-workflow.md를 적용해줘.
필요한 기존 구조만 읽고 로컬 변경사항을 보존해줘.

도시의 성격:
- 강을 이용한 곡물 운송과 거래가 중심이다.
- 동쪽에 강, 서쪽에 육로 진입로, 북쪽에 농경지가 있다.
- 나루·곡물 창고·시장·주거지·관청이 필요하다.
- 우선 외부 탐험 공간을 설계하고 실내는 별도로 둔다.

지형을 먼저 정하고 도로·구역·건물을 배치해줘.
도로부터 대문·마당·문까지 동선을 연결하고,
시설의 위치와 방향을 사람·물자의 이동으로 설명해줘.
공공 통행과 사유 마당·작업 공간을 구분하되
모든 건물에 동일한 마당과 담장을 요구하지 마.

다음을 제시해줘.
1. 구역별 역할과 인접 관계
2. 주요 도로와 물자·주민 이동 동선
3. 건물 부지·입구·하역/작업 공간의 배치안
4. 기존 에셋으로 가능한 부분과 새 미술이 필요한 부분
5. 먼저 제작할 대표 구역과 선정 이유
6. 불확실한 조건과 규칙의 예외

이번에는 설계만 한다.
새 미술·NPC·퀘스트·실제 맵은 만들지 않고,
기존 파일 수정과 GitHub 업로드도 하지 않는다.
```

## 2. 대표 구역 제작과 실제 크기·통행 확인

주요 관계를 포함한 작은 구역부터 만든다. 강변 곡물 도시라면 나루 일부→창고 하역장→시장 진입로가 예다. 기존 승인 에셋과 코드를 우선 사용해 도원/건물/도로의 크기, 문 방향과 접근, 작업/통행 분리, 가림/정렬, 플레이 화면의 이해 가능성을 확인한다. 임시 에셋의 한계는 명시한다. 배치가 안정된 뒤 필요한 새 미술을 제작한다.

```text
앞서 설계한 도시에서 나루·창고·시장 진입로를 포함하는
대표 구역 하나를 제작해줘.

AGENTS.md와 docs/CLI_HANDOFF.md를 먼저 읽고
필드 구성 원칙과 맵 제작 작업 순서를 적용해줘.
기존 프로젝트의 독립 시험 씬으로 구성하고,
본게임 적용은 별도 작업으로 남겨줘.

- 기존 에셋과 배치·충돌·정렬 코드를 우선 재사용한다.
- 기존 도원 크기·속도·배율·보간을 유지한다.
- 부지·도로·출입문·하역장·통행로의 연결을 구현한다.
- 새 미술·NPC·퀘스트·상품은 추가하지 않는다.
- 부족한 에셋은 임시 표현임을 명시한다.

제작 전 수정 파일과 구현 범위를 짧게 안내하고 로컬 변경을 보존해줘.
제작 후 규칙에 따라 직접 검토하고,
출입·통행·충돌·정렬과 기본 이동을 필요한 범위에서만 검증해줘.
시각 확인은 대표 화면 몇 장으로 제한하고 영상은 만들지 마.

결과에는 공간 구조의 성립 여부, 시각 문제,
임시 에셋 때문에 판단할 수 없는 부분,
전체 도시로 확장하기 전에 필요한 수정을 포함해줘.

관련 파일만 GitHub에 올리고 실행 경로를 알려줘.
허락 요청이 필요하면 한국어로 설명해줘.
```

## 3. 확인된 기준으로 도시 전체 확장

대표 구역에서 확인한 도로 폭·부지·출입·축척을 재사용하되 시장과 주거 골목처럼 용도에 따른 차이를 둔다. 나머지 구역을 같은 배치로 복제하지 않는다. 필요한 미술만 목록으로 정리하고 기존 승인 원본을 실제로 확인한 뒤 같은 화풍/축척으로 제작한다. 전체 주요 동선을 연결해 확인한다. NPC·퀘스트는 공간이 안정된 다음 별도 작업으로 넣어 지형 문제와 콘텐츠 연결 문제를 구분한다.

```text
확인된 대표 구역과 도시 설계안을 기준으로
도시의 나머지 외부 구역을 구성해줘.

AGENTS.md와 docs/CLI_HANDOFF.md를 먼저 읽고
필드 구성 원칙과 맵 제작 작업 순서를 적용해줘.
로컬 변경사항을 보존해줘.

- 대표 구역에서 유지할 축척·도로·부지 기준을 먼저 정리한다.
- 각 구역은 용도와 주변 지형에 맞게 배치한다.
- 규칙을 제작 중 적용하고 완료 후 직접 검토한다.
- 주요 시설의 배치 이유와 사람·물자의 접근 동선을 확인한다.
- 새 미술이 필요하면 기존 원본을 실제로 확인하고 필요한 종류만 제작한다.
- NPC·퀘스트·실내·새 시스템은 이번에 추가하지 않는다.
- 본게임 적용 범위는 작업 시작 시 명확히 안내한다.

전체 동선과 지역 연결, 출입 접근, 충돌·정렬을 확인하되
이미 통과한 관련 없는 검사는 반복하지 마.
영상·불필요한 캡처·NPC 혼잡도 시험은 진행하지 마.

완료 후 변경점, 규칙의 예외, 검사 결과와 미확인 범위를 짧게 보고해줘.
관련 파일만 GitHub에 올리고 실행·업데이트 방법을 제공해줘.
허락 요청이 필요하면 한국어로 설명해줘.
```

## 작업 비용과 범위

- 단계마다 실제로 필요한 부분만 수정하고, 검증된 기준과 검사 결과를 재사용한다. 새 기능·새 위험·실패가 생겼을 때 관련 검사만 추가/재실행한다.
- 게임 수치·도원 크기·이동 속도·배율·보간을 맵 수정에 맞추려고 임의로 바꾸지 않는다.
- 새 맵/실제로 수정하는 구역부터 적용한다. 기존 맵 전체를 일괄 개편하지 않는다.
- NPC·퀘스트 추가는 별도 명령과 추가분 검증으로 처리한다. 보류한 NPC 혼잡도 시험은 재개 요청 전까지 실행하지 않는다.
- 사용자가 설계만 요청하면 설계 단계에서 끝낸다. 각 단계 안의 통상적 구현 선택은 현재 승인 범위에서 진행하고, 지침을 이유로 매번 형식적인 승인을 요구하지 않는다.
- 사용자는 최종 화면과 플레이 경험의 의도 적합성을 판단한다. 제작자가 규칙 적용·통행/연결 검토를 담당하고 판단이 필요한 예외와 미확인 사항을 보고한다.
