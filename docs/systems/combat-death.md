# 주요 전투 사망과 타이틀 복귀

사용자 확정(2026-10-26): 청애채 전투에서 패배하면 사망하여 여정이 끝나고 처음 실행할 때의 타이틀 화면으로 돌아간다. 이후 주요 전투도 사망이 기본이다.

## 현재 동작

1. 청애채 감옥지기 정괴전에서 체력0.
2. 전투 진행/입력을 중단하고 주인공이 쓰러지는 모션을 재생한다.
3. 짧은 암전 후 **강호에 쓰러지다 / 도원이 목숨을 잃었습니다** 종료 화면을 표시한다.
4. 종료 화면의 **처음 화면으로 · F / Enter** 버튼 또는 해당 키로 확인하면 처음 타이틀로 돌아간다. 연출 도중 누른 키는 건너뛰기/자동 재도전으로 처리하지 않는다.
5. 타이틀에서 기존 저장을 불러오거나 새 여정을 시작한다. 프로그램 자체를 종료하는 기능이 아니다.

사망 시 탐험·대화·I/K/Q/R/L/F2/설정·저장·현장 재도전은 열지 않는다. 일반 전투 자동 결산 창도 사망 화면을 가리지 않도록 표시하지 않는다. 보상/의뢰 완료/후퇴 후 재도전 대사는 실행하지 않는다. 이전 수동 저장과0장 체크포인트 파일을 삭제하거나 자동 덮어쓰기하지 않는다.

타이틀 복귀는 기존 `reset()` 경로를 사용해 죽은 인물의 회전·색·전투 입력/트윈과 현재 진행을 정리한다. 저장을 다시 불러올 때는 저장한 시점으로 돌아가며 사망한 진행을 자동 보존하지 않는다. 연출 중 별도 초기화가 일어나면 지연된 종료 화면 표시도 취소한다.

## 공통 결과 규칙

`combat_outcome.gd.defeat_policy(encounter)`는 조우의 `defeat_outcome`을 읽는다.

| 값 | 의미 |
| --- | --- |
| `death` 또는 생략 | 사망·종료 화면·타이틀 복귀 |
| `nonlethal` | 비살상 대련, 해당 의뢰의 패배 처리 |
| `retry` | 명시적으로 허용한 기존 후퇴/재도전 처리 |

알 수 없는 값은 사망으로 처리한다. 새 주요 전투에 별도 재시도 예외를 자동 부여하지 않는다. 조우가 비어 있는 기존0장 튜토리얼/전투 체험은 이전 재도전 방식의 예외다.

후속 사용자 확정(2026-10-28)으로 구칠(약초꾼 구출)·장만길(객잔 시비)·마응칠(무림맹 사칭범)도 `death`다. 패배 후 후퇴/재도전 대사와 자동 결산창을 열지 않는다. 장만길과 싸우기 전에 말로 중재하는 경로와 승리 보상은 유지한다. 장사 산적2전은 `retry`, 유소강 대련은 `nonlethal`, 빈 조우0장은 재도전 예외를 유지한다. 이전 저장에서도 조우 정책은 현재 데이터의 사망 규칙을 따른다.

감옥 앞 구출 선택에 사망 경고와 확인창을 추가했다. 결정을 보류하고 창을 닫아 전투 전 저장/정비할 수 있다.

## 검사와 화면

`tests/death_flow.gd`에서 청애채 감옥지기의 실제 적 공격으로 체력0을 만들고 사망/메뉴 차단/저장 차단/회전 모션/확인 타이틀 복귀를 확인한다. F·마우스 버튼 경로, 동일 저장 파일 내용 보존과 재로드, 기존 비살상 대련/장사 후퇴 예외, 미지정 신규 전투의 기본 사망, 초기화 시 지연 연출 취소도 확인한다.

`tests/qingya_quest.gd`의 과거 재도전 기대값은 새 경고/진입 규칙으로 바꾸고 두 생존 결말·보상·폐허 흐름을 회귀 검사한다. 기존 `saves`, `combat_updates`, `bandit_story`, `prologue_f_input`도 관련 회귀 검사로 사용한다. 모든 검사는 실제 플레이와 분리한 XDG 폴더에서 실행한다.

원본 스프라이트는 수정하지 않고 기존 피격 자세와 게임 트윈으로 연출한다. `capture_death.gd`는 사망 처리에 실제 쓰이는 렌더러를 캡처하며 배포용 데모/EXE는 만들지 않는다.

후속 사용자 수정으로 후육전·마운표전은 신규 의뢰 경로에서 제거했다. 현재 실제 청애채 전투는 일반 감옥지기 정괴 한 명이며 저장 호환 ID는 `qingya_chief`를 유지한다.

`tests/wuchang_lethal_losses.gd`는 변경된 세 상대의 실제 격자 공격으로 체력0→사망/저장 차단/무보상→확인 후 타이틀을 각각 검사한다.
