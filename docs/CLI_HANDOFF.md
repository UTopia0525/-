# CLI 작업 인계 — 2026-10-22

## 현재 상태

**최신 구현:** Godot에서 0장 전체 대사·침몰·귀물/구조 선택·귀물 인도 보수 3,000문·장사 항구 최종 대화·항구 자유 탐험을 연결했다. `docs/story/chapter-00-implementation.md`를 먼저 확인한다. 아래의 ‘첫 전투까지/침몰 미구현’ 기록은 과거 단계다. 장사 9개 퀘스트 기능은 여전히 미구현이다.

최신 후속 작업은 **Godot 4 프로젝트(`godot/`)**이다. 사용자가 브라우저 데모 탐험 화면의 도트 그래픽·분위기에 아쉬움을 표현해 나루터·갑판·캐릭터 시안을 새로 제작하고 Godot 네이티브 이동·충돌·길 찾기·대화·첫 전투로 연결했다. `godot/README.md`를 먼저 읽고 `godot/project.godot`을 연다. 사용자는 현재 Godot 탐험 화면에 만족했고, 후속 요청에 따라 걷기 프레임과 BGM을 아래 업데이트로 추가했다. 전경 레이어 등은 후속 작업이다.

아래 브라우저 구현은 이전 비교용 버전으로 보관한다.

명 초기(1390년경)를 배경으로 하는 무협 RPG 기획이다. 탑다운 도트 탐험 + 별도 1인 턴제 전투를 사용한다. 현재 HTML/CSS/JavaScript 기반의 작은 실행 데모를 demo/에 구현했다. 출항 전 나루터 대화·도트 탐험·승선·갑판 보고·흑린채 첫 전투까지 실행되며 demo/index.html을 브라우저에서 열면 된다. 전체 게임 엔진은 아직 결정하지 않았다. 세계 지도는 world-map/index.html로 실행 가능하고, prototypes/의 화면들은 클릭할 수 없는 이미지 시안이다.

## 현재 전투 설정

- 기본 스탯은 근력·기민·근골·내공·오성. 각각0~100.
- 합계가100이면 절정, 200이면 초절정, 300이면 화경, 400이면 현경, 500이면 자연경. 기준 이상에서 승급하며 0~99 명칭은 미정.
- 경지는 무공 습득 조건에 사용한다. 개별 무공의 스탯 요구치와 전수 자격은 별도로 정한다.
- 최대 체력은 다섯 스탯 외 별도로 올릴 수 있고 경지 합계에는 포함하지 않는다. 성장 수단·증가량·상한·근골의 체력 기여는 미정.
- 기본 피해 공식은 D=공격 측에서 계산한 방어 전 전체 피해, G=방어자의 근골일 때 max(0,D-G)*100/(100+G). 소수 정수화 방식 미정, 최소 피해1을 자동 추가하지 않는다.
- 시작 캐릭터 기준안은 모든 스탯10, 최대 체력300. 초기 무공 삼재검법의 전체 피해는 근력*3+기민*2이므로50.
- 초기 적 기준안: 근골5, 체력150. 삼재검법 피해는 약42.86으로 4회 명중 시 처치. 적 공격력과 나머지 스탯은 미정.
- 각 전투는 최상의 컨디션으로 시작하고 이전 체력 손실은 이월하지 않는다. 탐험 화면에는 체력을 표시하지 않고 전투 화면에서 표시한다. 내기는 아래 최신 전투 자원 규칙을 따른다. 상태 이상·패배 처리의 세부 규칙은 미정.
- 전투는 주인공 1명. 왼쪽 아래에서 등을 비스듬히 보여 주며 오른쪽 위 적과 대치한다.
- 우측 하단2×2 슬롯 중 첫 칸은 기본공격으로 고정하고 나머지3칸에 습득 무공을 편성. 초기에는 기본공격·삼재검법·빈칸2개.
- 슬롯을 클릭하면 즉시 공격하지 않고 왼쪽에 설명을 표시한다. 구체적인 무공 효과는 사용자가 추후 설정한다.
- 별도 ‘사용’ 버튼은 현재 v2 시안의 제안이며 사용자가 명시 확정한 조작은 아니다. 전투 중 편성 변경 여부도 미정.

## 스토리 진행 범위

- 본편 전체 스토리는 보류. 현재 호송선 사건을 0장 프롤로그/튜토리얼로 설정했다.
- 출항 전 준비는 몰입용 공통 진행이며 성과·보상 분기를 추가하지 않는다.
- 흑린채와의 전투가 튜토리얼. 배가 침몰하고 표사 대부분이 수장되어 표국이 자연스럽게 해체된다. 본거지 공격·표국 전원 사망을 추가하지 않는다.
- 핵심 선택 A: 귀물을 지킴 → 수령 대상에게 인도 → 해체된 표국 대신 주인공이 대가를 받아 유리하게 출발하지만 구하지 못한 사람에 대한 죄책감이 남음.
- 핵심 선택 B: 사람을 구함 → 귀물 전달 불가 → 수령 대상에게 표행 실패 사실만 보고 → 해당 대가를 받지 못함.
- 어느 경로든 주인공은 표국 해체 후 무소속으로 자유 플레이를 시작한다. 강제 배상·대체 임무를 추가하지 않는다.
- 귀물의 정체·수령인·표국 이름·이후1장 이야기는 미정이다. 보수는 최신 원고 기준 3,000문이며 구조 인물 배역은 아래 최신 원고 제안을 따른다. 앞서 제안했던 장부 회수 분기는 폐기되었다.

사용자가 만족한 Godot 버전에 주인공 4방향×4프레임 걷기와 정지 자세를 연결했다. 기존 상하 흔들림은 제거했고 대화·정지·벽 충돌에서 idle로 돌아간다. `godot/assets/animation/README.md` 참고.

상황별 원본 합성 BGM 5곡을 `godot/assets/music/`에 각60초 스테레오 OGG로 저장했다. 타이틀·나루터·항해·습격 전 긴장·전투를 구분하며 `scripts/music.gd`에서 자동 반복·교차 페이드한다. M키로 음악을 끄고 켠다. 편집용 MIDI/악보 JSON과 재합성 도구도 저장했다. 실제 전통악기 녹음이 아닌 직접 합성한 무협풍 음악 시안이다.

이번 요청은 프로젝트 소스/자산만 업데이트하는 것이다. 별도 새 데모/EXE/새 캡처를 만들라는 요청이 아니며 기존 진행 범위를 확장하지 않는다. 음악 및 동작 관련 세부 내용은 Godot README와 각 자산 README를 따른다. 전투 규칙과 미정 설정은 변경하지 않았다.

## BGM 용도 부제

음악에 관한 구체적인 청취 피드백은 추후로 보류했다. 기존 곡명을 유지하면서 공용 상황 부제를 붙였다: 강호의 여명 — 타이틀·회상 시 / 나루의 아침 — 일반 맵 이동 시 / 물결 위의 표행 — 평온한 대화·휴식 시 / 갈대 속의 그림자 — 긴장·위기 시 / 흑린의 칼끝 — 일반 전투 시. 곡은 특정 장소 전용이 아닌 상황별 공용 풀로 활용한다. OGG 표시 제목, 목록, manifest 및 편집 원본에도 부제를 기록한다.

## 탐험 카메라 — 사용자 확정 방식

WASD 이동을 유지하고, 맵 안쪽에서는 주인공의 몸 중심을 카메라가 추적한다. 맵 경계에 도달하면 해당 축의 카메라는 고정되고 주인공만 화면 안에서 움직인다. `godot/scripts/follow_camera.gd`의 Camera2D와 맵 경계 제한을 사용한다. HUD·대화·전투는 별도 CanvasLayer라 화면에 고정된다.

현재 맵은 창과 같은 1280×720이므로 기본 탐험 배율을 1.5로 두어 추적을 확인할 수 있게 했으며 `exploration.gd`의 camera_zoom으로 조정 가능하다. 더 넓은 맵은 map_bounds·통행 영역·배치를 함께 정의하면 같은 추적 방식을 활용한다. 맵 자체의 면적을 늘린 것은 아니다. 기존 프로젝트 소스만 업데이트하며 새 데모 배포본·캡처는 만들지 않는다.

## 엑스트라 공용 초상화와 대화 참여자 표시

사용자 요청으로 남/녀 × 청년/중년/노인 총 6종의 공용 대화 일러스트를 `godot/assets/portraits/extras/`에 추가했다. 특정 인물 디자인·성격·전투 수치를 확정한 것이 아니다. 현재 주인공·육승은 청년 남성, 서문길·허만복은 중년 남성, 진소옥은 청년 여성 공용 시안을 사용하며, 나중에 전용 일러스트로 교체할 수 있다.

대화 전체 참여자와 듣는 인물은 처음부터 함께 표시하며, 말하는 인물만 원래 밝기이고 다른 인물은 어둡게 처리한다. 발언자 변경 시 자리와 그림은 유지한다. 전용 일러스트가 등록되어 있으면 공용 초상화보다 우선한다. `scripts/dialogue_portraits.gd`에서 인물 ID별로 관리하므로 같은 공용 그림을 공유해도 발언자를 구분한다. 기존 프로젝트만 업데이트하며 별도 배포 데모/EXE/캡처는 새로 만들지 않았다.

## 주인공 전용 대화 초상화 — 2026-10-23

사용자 지정: 젊은 남성, 무표정이 기본이며 소탈하지만 해지지 않은 복장. 어떤 무기를 쓸지 미정이므로 무기는 그리지 않는다. `godot/assets/portraits/player/hero.png`에 저장하고 대화 인물 등록의 `hero.portrait`에 연결했다. 앞서 주인공에게 임시 사용하던 공용 청년 남성 그림을 대체한다. 엑스트라 6종과 듣는 인물 어둡게 처리하는 규칙은 유지한다. 대화용 일러스트 추가이며 탐험·전투 스프라이트, 전투 수치, 스토리 범위는 변경하지 않았다. 별도 새 데모 배포본은 만들지 않는다.

## 주인공 복식 수정 — 낭인 분위기

주인공이 향후 소속 없는 낭인이 될 예정이라는 사용자 설명에 맞춰 대화 초상화를 수정했다. 넓은 챙의 삿갓과 느슨하게 겹쳐 입은 여행용 옷으로 자유로운 분위기를 더한다. 얼굴과 눈이 보이도록 삿갓을 살짝 뒤로 젖히고, 젊은 남성·무표정·소탈하지만 해지지 않은 옷·무기 없음은 유지한다. `godot/assets/portraits/player/hero.png`를 갱신하므로 기존 대화 연결에 자동 반영된다. 0장의 소속·진행이나 탐험·전투 스프라이트를 변경한 것은 아니다.

주인공 삿갓 착용 오류 수정: 삿갓 밖으로 올라오던 상투를 없애고, 상투를 안에 수용하는 막힌 삿갓 윗부분으로 수정한다. 얼굴·눈이 보이는 착용 각도와 기존 복식·표정은 유지한다.

## 0장 이후 첫 거점 — 장사 도시 맵

사용자가 장사를 첫 자유 탐험 도시로 채택하고, 퀘스트에 앞서 도시와 주변 농촌 맵 제작을 요청했다. `godot/assets/maps/changsha/`에 전체 배경과 통행·장애물·주민·구역 데이터를 저장했다. 게임 크기 6144×4096이며 나루·하역장·시장·객잔·관아 앞·공방·주거지·사당 정원·동문 밖 농촌을 연결한다. 실제 명대 도시 평면의 복원도가 아닌 게임용 창작 배치다.

타이틀의 ‘장사 자유 탐방’으로 따로 입장한다. WASD·바닥 클릭 이동, 중앙 추적 카메라와 경계 제한, TAB 전체 지도·현재 위치, 구역 HUD, 기존 일반 맵 BGM을 적용했다. 생활 풍경용 주민 30명은 대사·퀘스트가 없다. 0장 후반부가 미구현이므로 0장 종료 뒤 자동 이동하는 스토리 연결을 만들지 않았다. 실내·상점 기능·퀘스트·대사·성장 보상·1장 진입 조건은 추후 설정한다. 별도 데모/EXE 배포본 없이 기존 Godot 프로젝트를 업데이트하고, 사용자 요청에 따라 도시 전체 이미지와 확인용 화면을 제공한다.

## 장사 초기 의뢰 9종 채택 — 2026-10-23

사용자가 제안된 의뢰 중 「울타리 밖의 닭」만 제외하고 나머지 9개를 채택했다. 최신 목록과 채택한 내용은 `docs/quests/changsha.md`를 따른다. 옷감 배달·바구니 교환·식기 회수·보따리 찾기·표식 짐 운반·장부 세 장 회수·농기구 자루 전달·물길 정리·노인과 아들 안부 전달이다. 마지막 의뢰의 전달 방식 선택은 후속 대사만 달라지는 작은 갈등으로 둔다. 퀘스트 기능은 아직 미구현이다. 보상 수치·고유 인물명·정확한 좌표·성장 효과·1장 진입 조건은 추후 설정하며 닭 의뢰의 대체안을 임의 추가하지 않는다.

## 장사 의뢰 9편 대화·연계 규칙 — 최신 사용자 확정

사용자가 옷감 배달 시안의 대화 방식을 9개 모두에 적용하도록 요청했다. `docs/quests/changsha-dialogues.md`에 수락·보류·진행 중·목표 NPC 대화/현장 조사·완료·완료 후 한마디를 모두 작성했다. 각 인물의 일 관련 잡담·말버릇·주민 관계를 포함한다. 직업으로 인물을 구분하고 고유 이름·보상 수치는 확정하지 않았다. 공용 초상화 분류와 발언자 강조 연출을 따른다.

연계는 사용자 답변으로 **옷감 배달 → 식기 회수 → 농기구 전달** 세 의뢰만 확정했다. 앞 의뢰 완료 후 다음 의뢰를 개별 수락하며 자동 수락은 없다. 나머지 여섯 의뢰는 처음부터 독립 수락·완료한다. 특히 물길 정리를 네 번째 연계로 붙이지 않는다. 기존 ‘9개 모두 독립/네 가지 추천 동선’ 설명보다 이 규칙이 우선한다. 노인·아들 의뢰의 전달 방식은 후속 대사만 바꾸며 메인 스토리·능력치·보상 차이를 추가하지 않는다. 새 원고는 기획 자료이며 퀘스트 진행과 대화 UI에 연결하는 기능은 아직 미구현이다.

## 장사 입성·자동 도입 연계와 일반 퀘스트 — 최신 규칙

사용자는 0장 종료 뒤 주인공이 장사 도시 입구에서 시작하고, 일거리를 찾는 혼잣말 후 성안에 들어가면 포목상이 먼저 말을 걸어 첫 의뢰를 자연스럽게 받도록 확정했다. 옷감 배달 → 식기 회수 → 농기구 전달 세 개는 의뢰 대화 후 순차 자동 수락하는 도입 연계다. 기존의 ‘세 개도 수락/보류를 선택하며 자동 수락하지 않는다’ 규칙은 이 설정으로 대체한다. 대화 원고에서 해당 선택지를 제거하고 도입과 후속 부탁을 수정했다. 포목상은 동문 안 첫 상점 어귀에 배치하도록 기획을 조정했다.

그 외 NPC 머리 위 노란 느낌표를 보고 대화하여 받는 의뢰는 사용자 지정 명칭 **일반 퀘스트**다. 장사의 나머지 여섯 개가 해당한다. 진행 중에는 진행 대사를 재생하고, 달성 조건 충족 후 노란 물음표로 바꿔 완료 보고 대화를 해야 완료 처리한다. 조건 충족만으로 완료·보상을 자동 지급하지 않는다. 상세 상태와 도입 흐름은 `docs/quests/quest-flow.md`가 기준이다. 이번 변경은 기획·원고 반영이며 입성 이벤트·퀘스트 상태·NPC 표식의 실제 Godot 구현은 아직 없다. 현재 자유 탐방의 런타임 시작점은 변경하지 않았다.

## 장사 선명도·NPC 깊이·미니맵 — 사용자 요청 반영

작은 도시 배경의 과도한 확대가 흐릿함의 원인이었다. `godot/assets/maps/changsha/detail/`의 구역 이미지 4개를 도입하고 배율을 1.0으로 조정했다. 상세 배경에 맞춰 충돌·주민·지점 좌표를 보정했다. NPC는 발끝 기준으로 정렬하고, 몸 전체가 지붕·노점 영역과 겹치지 않게 재배치하며, 배경 오브젝트를 Y 정렬로 덧그려 뒤에 있는 캐릭터를 가린다.

좌상단 위치 패널은 `scripts/minimap.gd`의 주변 지형 미니맵으로 교체했다. 구역명·금색 플레이어 화살표·청록색 NPC 점을 실제 월드 위치에 맞춰 갱신한다. 전체 지도와 미니맵도 4개 구역을 표시한다. 실제 Godot 캡처는 `godot/screenshots/changsha-market-ui-revised.png`다. 퀘스트 표식·진행 기능은 이번 작업 범위에 추가하지 않았다. 별도 데모 배포본을 만들지 않고 기존 프로젝트를 업데이트했다.

## 장사 NPC 배치와 퀘스트 안내 — 최신 구현

주민 30명 중 의뢰 원고 관련 14명에게 NPC ID·역할·배치 장소를 부여하고, 생활 주민 16명과 함께 길 중앙을 피하도록 재배치했다. `layout.json`의 `road_centers`는 배치 검사용이며 보행 장애물이 아니다. 미니맵의 주황색 마름모는 추적 목표, 범위 밖 가장자리 화살표는 목표 방향이다. TAB 지도에도 주민·목표를 표시한다.

`quest_navigation.gd`에 명시적인 단계 추적 API, `data/changsha_navigation.json`에 9개 의뢰의 목표 데이터를 추가했다. NPC는 실제 위치를 추적하며 여러 목표는 남은 가까운 지점, 전부 달성 후에는 보고 NPC를 안내한다. 퀘스트 수락·판정·대화·보상·느낌표/물음표는 아직 구현하지 않았다. 기본 탐방은 추적 퀘스트가 없다. `changsha-navigation-outside.png`와 `changsha-navigation-inside.png`는 캡처 스크립트에서 옷감 전달 목표를 지정한 안내 예시다. 세 도입 연계와 여섯 독립 의뢰 규칙은 유지한다. 상세 내용은 `docs/quests/quest-navigation.md`와 `tests/quest_navigation.gd`를 참고한다. 기존 Godot 프로젝트만 수정하고 EXE/새 데모 배포본을 만들지 않는다.

## 도시 공통 6구역·장사 시설 NPC — 최신 사용자 확정과 구현

앞으로 모든 도시에 상점가·관아·무관·공방거리·객잔·주거구역을 둔다. 추가 구역은 사용자 지정 또는 도시 특성으로 채운다. 공통 데이터는 `godot/data/city_standards.json`, 설명은 `docs/cities/city-standards.md`다. 장사는 상강 나루·하역/창고거리·성밖 농촌을 유지하고, 기존 남동쪽 건물과 앞마당을 무관으로 지정했다. 남쪽 사당·정원은 별도 구역으로 남긴다. 전체 지도 구역은 11개다.

생활 주민 3명을 장사꾼·장인·교관으로 바꿔 각각 상점가·공방거리·무관 앞에 배치했다. 주민 총 30명, 기존 의뢰 관련 14명은 유지한다. 가까이에서 F 거래 → 공용 초상화 인사 대화 → 시설 창을 열고 ESC/돌아가기로 닫을 수 있다. 상점 구매/판매, 공방 제작/수리, 무관 수련/무공 전수는 내용을 채울 임시 탭이다. 사용자 요청에 따라 구체 품목·가격·재화·무공·수련 효과·실제 거래 처리는 아직 정하지 않고 비워 뒀다. 시설 창만 열리는 상태를 실제 거래 완료 기능으로 설명하지 않는다. `tests/city_services.gd`에 배치·대화·창 전환·이동 중지/복귀·초기화 검증을 추가했다. 기존 Godot 프로젝트만 업데이트하고 별도 데모/EXE 배포본은 만들지 않는다.

## 상호작용 키 고정 — 최신 사용자 확정

대화·다음 대사·승선·시설 거래 진입은 **F키**로 통일한다. 기존 E키와 탐험 중 Enter 대체 입력은 사용하지 않는다. `interact` 입력 액션에 물리 F키를 등록하고 해당 액션으로 상호작용을 처리한다. 화면 근접 안내·하단 조작법·문서도 F로 통일했다. 전투의 Enter 무공 선택/실행과 F1 초기화는 유지한다. 이전 캡처에 E 안내가 남아 있으면 과거 이미지이며 최신 조작 기준은 F다.

## 0장 전체 대화 원고·보수 화폐 — 최신 작성

사용자는 0장을 마무리할 대화를 요청했고, 두 선택 모두 후회가 남도록 강조했다. `docs/story/chapter-00-dialogues.md`에 나루·승선·흑린채 튜토리얼 전투·침몰·귀물/구조 선택·표국 해체·수령인 보고·장사 입성까지 전체 원고를 작성했다. 실제 Godot 후반부 구현은 아직 하지 않았다. 귀물 인도 보수는 사용자 지정 수치 3,000에 명 초기 배경의 동전 단위 **문(文)**을 적용해 **3,000문**으로 정리한다. 명목상 3관으로 읽으며 게임 표기상 1,000문=1관이다. 현대 원화 구매력이나 당시 지폐/동전 실환율을 환산한 금액이 아니다. 구조 경로는 해당 보수 0문이며 다른 초기 소지금은 미정이다.

귀물 보전은 돈을 받아도 구조하지 못한 사람에 대한 죄책감, 구조는 살아난 사람을 보며 안도하면서도 잃은 품삯과 앞날을 생각하는 자신에 대한 불편함을 남긴다. 허만복을 구조 대상으로 두고 구조 경로에서 귀가시키는 것은 이번 원고의 배역 제안이다. 귀물 정체·수령인 고유명/소속·표국 고유명과 다른 인물의 개별 생사는 확정하지 않는다. 구조 경로는 실패 사실만 보고하며 배상·대체 임무·숨은 금전 보상을 추가하지 않는다. 어느 쪽도 표국 해체 후 무소속으로 장사 입구에 도착한다. 장사 입구의 기존 혼잣말은 중복 재생하지 않는다. 본편 1장 이야기는 여전히 보류다.

## 0장 전체 게임 연결 — 최신 사용자 요청 반영

대화 원고를 실제 Godot에 구현했다. `scripts/export_prologue_dialogue.py`가 원고 156줄을 25장면의 `godot/data/prologue_dialogues.json`으로 내보낸다. 필수 표두 인사·선택 방문·승선·갑판 보고 후 실제 첫 전투를 마치면 `prologue.gd`가 침몰·선택·표국 해체·정산·항구 독백을 진행한다. F키 대화, 발언자 강조, 속말/회상 이름 표기, 상황 BGM을 연결했다. 핵심 선택은 기본값 없이 고른 뒤 Enter/별도 실행 버튼으로 확정하며 F 연타로 확정되지 않는다.

귀물 경로는 인도 확인 후 3,000문을 일회 지급하고, 구조 경로는 허만복이 생존하며 보수가 없다. 이번 런타임의 별도 초기 재산은 미설정이므로 새 표행은 0문으로 초기화한다. 이는 다른 초기 재산 기획의 확정이 아니다. 소지금은 탐험 HUD에 표시한다. 최신 사용자 요청으로 수령인과의 정산/실패 보고와 마지막 독백 모두 장사 항구에서 진행하며, 끝나면 원본 맵 좌표 [280,500]에서 무소속 자유 탐험을 시작한다. 기존 동문 시작 초안보다 항구 진입이 우선한다. 장사의 첫 자동 도입 퀘스트·일반 퀘스트 진행 기능은 이번에 추가하지 않았다.

0장 완료 시 `user://chapter_00.json`에 선택·보수 수령·소지금 체크포인트를 기록하고 타이틀 ‘0장 이후 이어하기’로 복원한다. 중간 저장이나 도시의 임의 위치 저장은 아니다. F1은 현재 표행을 취소하지만 기존 완료 체크포인트를 삭제하지 않는다. 새로 0장을 완료하면 최신 결과로 갱신한다. ‘전투만 체험’ 결과 화면은 별도 모드로 유지한다. 기존 배경과 Godot 수면/잔해 드로잉으로 컷신을 연출하고 전용 침몰 그림은 만들지 않았다. 별도 EXE/새 데모 배포본은 만들지 않는다. 검증·실제 양쪽 경로 캡처는 `tests/prologue.gd`, `tests/capture_prologue.gd`를 따른다.

## 1장 도입 대화·첫 연계 수락·중앙 표시 — 최신 구현

사용자는 0장 마지막 항구 대화 뒤 자유 탐험을 바로 시작하지 않고 기존 포목상 도입으로 직결하도록 요청했다. 여기부터 1장이다. `chapter_one.gd`가 포목상 12줄 대화 → 첫 의뢰 `changsha_cloth` 실제 수락(active/deliver) → 중앙 ‘1장’ 페이드 한 번 → 이동 재개를 처리한다. 제목은 사용자가 추후 결정하므로 부제를 만들지 않는다. 포목상은 항구 앞 [330,485]로 옮겼고 길 중앙·건물 겹침과 접근 가능 여부를 검증한다. 미니맵은 객잔 점소이를 안내한다. 세 의뢰를 동시에 수락하지 않으며 배달·완료 판정과 다음 의뢰 기능은 아직 없다.

완료 저장을 버전 2로 올려 도입/표시 완료·수락 상태를 저장한다. 예전 버전 1 저장은 0장을 다시 하지 않고 포목상 도입부터 이어간다. 완료 후 로드하면 대화·장 표시를 반복하지 않는다. 장 표시 중 F1 초기화 시 Tween을 취소한다. 상세 기준은 `docs/story/chapter-01-intro.md`, 검증은 `tests/chapter_one.gd`다. 기존 별도 도시 탐방은 스토리/퀘스트 없는 미리보기로 유지한다.

## 설정·수동 저장 10칸 — 최신 구현

설정 버튼/ESC에서 저장·불러오기 슬롯 10개를 제공한다. `save_system.gd`가 장·맵/좌표·대화 줄과 다음 진행·분기/지급 여부·소지금·1장 수락/표시 상태·목표 추적·시설 탭·내 차례 전투를 파일로 보존한다. 선택창 자체를 저장해 다른 경로로 돌아갈 수 있다. `settings_menu.gd`는 게임을 일시 정지하며 덮어쓰기/불러오기 확인을 제공한다. 공격 타이머도 process_always=false로 바꿔 설정 중 진행되지 않게 했다. 타이틀/장 표시/공격 연출 중에는 저장 불가 이유를 표시하며 연출 뒤 내 차례에 저장한다.

수동 파일은 `user://saves/slot_01.json`~`slot_10.json`, 기존 `chapter_00.json` 체크포인트는 별도 유지한다. 임시 파일 교체와 이전 파일 .bak 보관, 형식 검증을 적용한다. 객체나 코드를 저장하지 않고 허용한 메서드 이름으로 대화 다음 진행을 재구성한다. 새로운 진행 콜백은 허용 목록에 등록한다. 저장은 PC 로컬이며 GitHub로 자동 동기화하지 않는다. 상세 기능·한계·경로는 `docs/systems/save-slots.md`, 검증은 `tests/saves.gd`, 화면은 `tests/capture_saves.gd`를 따른다. 분기 이전 복귀·반대 결말·보수 중복 방지·새 인스턴스 로드·기존 기능 검사를 통과한 뒤 배포한다.

## 내기 전투 자원 — 최신 사용자 확정과 구현

내공과 별도로 내기(최대500)를 추가한다. 전투 시작량=내공, 턴 회복량=내공이다. 이번 구현의 회복 시점은 다음 주인공 턴 시작이며 첫 턴에는 시작 지급만 적용한다. 내기 자체는 경지 합계/피해 방어 공식에 더하지 않는다. 새 전투는 이전 잔량을 이월하지 않고 내공만큼 시작한다. 현재 내공10이므로 내기10에서 시작한다.

`inner_qi.gd`에 자원 상태, `battle.gd`에 표시·턴 회복·기술 비용 지불 API를 연결했다. 비용 부족 시 공격/턴 소모를 막고 선택 미리보기에는 지불하지 않는다. 삼재검법의 내기 비용은 미정이며 UI에 미정으로 표시한다. 현재 실행상 미설정 비용은 임시0으로 기존 전투를 유지한다. 개별 공격/방어 기술의 비용·효과는 추후 사용자 지정으로 채운다. 수동 저장 schema2에 내공/잔여 내기를 기록하고 schema1 전투 저장도 턴수×기본내공으로 최대500까지 복원한다. 새 적 스탯은 부여하지 않는다. 세부 기준과 검증은 `docs/systems/inner-qi.md`, `tests/inner_qi.gd`를 따른다.

## 삼재검법 비용10 확정·상위 초급 공격 무공10종 — 최신 작업

사용자는 삼재검법을 근력×3+기민×2, 내기10으로 확정했다. `basic_martial_arts.json`과 전투 실행/설명에 반영했으며 이전 ‘비용 미정/실행상0’ 기록을 대체한다. 요청한 신규 공격10종은 `docs/martial-arts/basic-attacks.md`와 같은 JSON에 피해 계수·내기12~28·개별 스탯12~18·총합60~80 조건으로 창작했다. 검/도/창/권/장으로 분산하고 획득처는 모두null이다. 신규10종의 수치는 제안이며 기존 NPC 스탯·세력 비기를 수정하지 않는다. 학습 가능 판정 API는 있으나 자동 습득·획득처·학습/편성 UI·신규 무공 전투 버튼은 연결하지 않는다. 플레이어는 여전히 삼재검법 하나로 시작한다. 무공 데이터 검증과 내기·전투·저장 검사를 실행한다.

## 무공 사용에 무기 장착 조건 추가 — 최신 사용자 확정

검법=검(sword), 도법=도(saber), 창법=창(spear)을 실제 장착해야 사용한다. 삼재검법 포함 전체11종에 `required_weapon_type` 필드를 추가했다. 권/장은 현재 특정 무기 조건을 두지 않으며 맨손 전용/권갑 필수를 임의 확정하지 않는다. 학습 조건과 사용 조건은 분리한다. `martial_arts.can_use_with_weapon()`과 전투 실행 직전 검사를 적용해 무기 불일치 시 사용 버튼을 막고 피해/내기/턴을 소모하지 않는다. 기존 튜토리얼은 검 분류를 기본 장착한다. 구체 아이템/등급/추가 능력치/장비 UI는 추가하지 않았다. 수동 슬롯의 weapon_type을 보존하고 과거 슬롯에 없으면 검으로 복원한다. 기준은 `docs/martial-arts/basic-attacks.md`, 검증은 `tests/weapon_requirements.gd`다.

## 시작 무문철검·검/도/창 각3등급 — 최신 설계와 적용

시작 무기는 부가 효과 없는 무문철검(plain_iron_sword)이다. 시작 검은 별도0등급이고 성장용 검/도/창을 각1~3등급, 총9종 제안했다. 검은 공격+5/10/15%와 피격피해-3/6/9%, 도는 공격+10/20/30%, 창은 창법 내기-10/20/30%다. 이름과 자료는 `docs/systems/weapons.md`, `godot/data/weapons.json`을 따른다. 신규9종 수치는 제안이며 획득/가격/소유/교체 UI/강화/내구도는 미정이고 자동 지급하지 않는다.

공격 보정과 창 비용 절감은 해당 무기로 쓰는 무공에만 적용하고, 검의 피해 감소는 장착 중 피격에 적용한다. 근골 공식 뒤 검 피해 감소를 곱한 후 한 번만 버림하며, 양수 내기 비용은 절감 뒤 올림·최소1이다. 무문철검은 기존 피해/소모/방어를 바꾸지 않는다. 무기 ID/분류를 수동 슬롯에 보존하고 이전 실제 플레이의 검 분류는 무문철검으로 복원한다. 분류 지정 API는 현재 소유/교체 UI가 아닌 내부 호환용이다. 검증은 `tests/weapons.gd`, `tests/weapon_requirements.gd`다.

## 창법·권법·장법 계열 조정 — 최신 사용자 요청

검법·도법 6개(삼재 포함)의 모든 필드는 유지했다. 관풍창법은 근12/기12/내12·합60, 피해 근3+기5+오2·내기20으로, 연환창법은 기15/내13/오12·합70, 피해 근3+기5+내3·내기34로 조정해 학습 문턱은 낮추고 피해/소모를 높였다. 철산권법은 근14/골14/내20·합80, 피해 근4+골3+내3·내기18; 진각권법은 근16/골16/내24·합90, 피해 근4+골2+내5·내기26; 운기장법은 내26/오18·합90, 피해 근1+내7+오3·내기28로 조정했다. 권/장은 `required_weapon_type=none`으로 무기 미장착일 때만 사용하며 null(제한 없음)과 다르다.

학습 조건을 충족해도 소비가 초기 내기보다 크면 첫 턴 사용이 불가능할 수 있다. 창을 든 채 삼재검법을 사용하는 것은 금지지만, 후속 확정된 무기 제한 없는 기본공격으로 내기를 축적할 수 있다. 대기/전투중 장비교체는 여전히 미정이다. 무기 절감은 연환창법 기준 34→유운창24로 계산한다. 수치와 변경표는 `docs/martial-arts/basic-attacks.md`를 따른다. 획득처/실제 습득/편성은 여전히 미정이다.

## 고정 기본공격

4슬롯 중 첫 칸은 항상 기본공격이며 무공 편성은 나머지3칸이다. 피해는 근력+기민+내공, 비용0, 무기 제한 없음. 내력이라는 표현은 기존 스탯 내공으로 해석하며 현재 내기량으로 피해를 계산하지 않는다. 다음 주인공 턴의 기존 내공만큼 회복으로 축적하며 별도 보너스 회복은 없다. 기본공격에는 무기별 무공 피해 보너스를 붙이지 않는다. 선택한 행동도 저장하고 구형 selected=true 슬롯은 삼재검법으로 복원한다. `tests/basic_attack.gd`와 `docs/systems/basic-attack.md` 참고.

## 하급 영약 4종 — 설정안

사용자는 근력·기민·근골·내공 중 하나를 주로 올리되 나머지3스탯도 올리는 영약4종을 요청했고 오성은 영약으로 올릴 수 없도록 확정했다. ‘근공’은 기존 근골로 해석했다. 웅력환(근력), 경신환(기민), 고골환(근골), 양기단(내공)을 창작하고 주력+3·나머지각+1·오성0을 제안했다. 일시 버프가 아닌 영구 기본 스탯 상승이며 각 스탯 상한100을 유지한다. 상승한 기본 스탯은 기존 경지 합계에도 포함한다. 자료는 `docs/systems/elixirs.md`, `godot/data/low_grade_elixirs.json`이다. 획득처·가격·반복 복용/내성은 미정이며 인벤토리·복용·스탯 성장·저장 기능에 아직 연결하지 않았다. 현재 플레이어 수치는 그대로 유지한다.
