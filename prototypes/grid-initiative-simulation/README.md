# 조절형 7×5 전투 실험실

[시뮬레이터 HTML](index.html) · [편집 화면](editor-configurable.png) · [재생 화면](editor-replay.png) · [기존31개 실험 보고서](../../docs/reviews/grid-initiative-paak.md)

## 사용하는 방법

1. `index.html`의 GitHub 화면 우측 위 **Download raw file**로 HTML 파일을 저장한다. GitHub의 코드 화면에서는 실행되지 않는다.
2. 내려받은 HTML 파일을 브라우저로 연다. 설치나 서버가 필요 없으며, 한 파일에 계산기·무공/무기 목록·기존 비교 조건을 포함했다.
3. **양쪽 캐릭터 설정**에서 값을 수정하고 **이 설정으로 다시 계산**을 누른다.
4. 이전/다음·재생·시점 막대로 새 전투의 이동/공격/내기/피해를 확인한다. 설정 창을 접으면 전장이 넓게 보인다.

편집 중에는 ‘설정 변경됨’을 표시하고 기존 결과를 유지한다. 다시 계산한 뒤에만 새 결과로 바뀐다. 잘못된 입력도 이전 전투를 덮어쓰지 않는다.

## 조절 가능한 항목

내 캐릭터와 상대 캐릭터 모두 같은 항목을 조절한다.

| 항목 | 범위/동작 |
| --- | --- |
| 이름 |최대20자. 화면에 문자 그대로 표시.|
| 근력·기민·근골·내공·오성 |각0~100 정수.|
| 체력 |1~100,000 정수.|
| 장착 무기 |맨손 포함11종. 기존 위력/방어/창 내기 절감 반영.|
| 무공 |기본공격·방어 포함24종에서 최대4칸 선택. 양쪽에 같은 목록 제공.|
| 시작 위치 |가로1~7, 세로1~5. 두 인물은 같은 칸에 둘 수 없음.|
| 자동 전투 방침 |강한 공격 우선 / 강공+3행동마다 방어 / 내기 회복 우선.|
| 속도 강제값 |비우면기민+10.1~500을 넣으면 게이지 속도만 고정하는 대조 실험.|
| 내기 회복 |공통 박자마다 / 자기 행동마다 내공만큼.|

무공은 **이미 배웠다는 가정**으로 실험하므로 학습 조건·가격은 검사하지 않는다. 장착 무기 조건·내기 소모·재사용 대기는 적용한다. 무기 불일치는 설정 아래에 경고하고 해당 무공을 사용하지 않는다. 편성한 공격을 사용할 수 없으면 기본공격, 사거리에 못 닿으면 접근 후 기본방어를 공통 보조 행동으로 쓴다.

기존31개 조건은 위의 ‘기존 비교 조건 불러오기’에서 선택할 수 있다. 실제 정괴280HP/검증용1,120HP·기민형/근력형/속도 고정형·5가지 시작 위치가 유지된다.

## 설정과 결과 저장

- **설정 내보내기/불러오기:** 스키마1 JSON으로 양쪽 캐릭터와 회복 방식을 보관한다. 설정 파일은100KB 이하. 검증에 실패하면 현재 설정/결과를 유지한다.
- **이번 결과 JSON 내려받기:** 입력 설정·전체 시점별 로그·최종 결과를 내려받는다. 설정 파일과 결과 파일은 다른 형식이다.
- 마지막으로 계산한 설정을 브라우저의 실험실 전용 저장 공간에 보관해 새로 열 때 복원한다. 브라우저가 저장을 막으면 기본 설정으로 실행하며 파일 내보내기/불러오기는 계속 사용할 수 있다.
- **실제 게임의 저장 파일·캐릭터·NPC·무공 데이터는 변경하지 않는다.**

## 전투 규칙과 실험 한계

- 가로7×세로5, 장애물 없는1대1. 기본 이동은 상하좌우 최대2칸, 이어 기술1개. 기술에 포함된 추가 이동/후퇴/밀치기는 별도다.
- 속도=기민+10, 게이지100마다 행동. 동일 시점에는 기민 높은 쪽 우선, 기민도 같으면 동률 우선권을 번갈아 준다.
- 시작 내기=내공, 최대500. 공통1박자는 기준 기민20의 게이지1회 충전 시간이며 실제 초 단위가 아니다. 공통 회복과 행동이 동시에 도착하면 회복부터 적용한다.
- 기존 피해 계수·무기 보정·내기 소비·20% 기본/검법 방어·조식수원공 회복/재사용 대기는 카탈로그 값을 사용한다. 방어는 다음 상대 행동1회 후 해제하고 중첩하지 않는다.
- [기본 무공 격자 재설계안](../../docs/martial-arts/grid-basic-redesign.md)의 전진/후퇴/관통 거리/밀치기/추격을 실험용으로 연결했다. 중급 도법은 전방3칸, 중급 창법은 직선2칸, 중급 권/장은 밀치기를 가진 가까운 범위로 가정했다. 적 전용 공격은 인접1칸이다. 이는 아직 본게임 확정 설정이 아니다.
- 자동 전투는 사용 가능한 강한 공격을 우선하며, 더 강한 편성 무공의 내기가 부족하면 회복 기술을 고려한다. 회복 우선은 내기를 더 여유 있게 확보한다. 회복 사용 전 기본 이동으로 접근할 수도 있다.3행동마다 방어 방침은 해당 차례에 자리를 지키고 방어한다. 모든 위치/남은 체력을 고려한 최적 전략을 보장하지 않는다.
- 명중·회피 난수/장애물/다수전/조준 예고 UI는 없다.200행동에서 끝나지 않으면 **상한 미결**로 표시한다. 유한 실험 조건은 승률 통계가 아니다.

## 소스/재현

- `engine.js`: 브라우저/Node에서 같은 순수 계산기를 사용한다. 실제 게임 런타임에서는 참조하지 않는다.
- `editor.js`, `editor.css`, `editor.template.html`: 편집/경고/계산/재생 UI.
- `catalog.json`: Godot 공통 계산기가 읽는 실제24무공/11무기의 내보내기 자료.
- `data.json`: 기존31개 Godot 실험의 원본 결과. 기준 비교용으로 보존한다.
- `index.html`: 아래 빌더가 모든 소스를 포함해 만드는 단일 파일이다.

```sh
# 기존 기준 결과가 필요할 때
XDG_DATA_HOME=/tmp/grid-initiative-data XDG_CONFIG_HOME=/tmp/grid-initiative-cfg XDG_CACHE_HOME=/tmp/grid-initiative-cache godot --headless --audio-driver Dummy --path godot --script res://tests/simulate_grid_initiative.gd
# 무공/무기 카탈로그 및 원본 계산 대조 자료 내보내기
XDG_DATA_HOME=/tmp/grid-editor-export-data XDG_CONFIG_HOME=/tmp/grid-editor-export-cfg XDG_CACHE_HOME=/tmp/grid-editor-export-cache godot --headless --audio-driver Dummy --path godot --script res://tests/export_grid_simulator_catalog.gd
python scripts/build_grid_initiative_replay.py
node scripts/test_grid_simulator.cjs
# Godot 내보내기 로그에 표시된 grid-oracle.json의 실제 경로를 인수로 주면 공통 계산까지 비교
node scripts/test_grid_simulator.cjs '/tmp/grid-editor-export-data/godot/app_userdata/가라앉은 약속 · Godot 0장/grid-oracle.json'
```

검증: 기존31개 조건의 행동/시점/체력/내기/이동을 정확히 재현했다. Godot의1,056개 스킬×무기×스탯 조합(유효356개/장비 불일치700개) 및 방어/근골별 피해를 대조했다. 전진/후퇴/밀치기/추격·재사용 대기·0스탯 상한 종료·잘못된 입력도 검사했다. 실제 브라우저에서 양쪽 스탯/무기/무공 편집, 재계산 전 결과 유지, JSON 가져오기/내보내기, 새로고침 복원, 인물 이름의 HTML 비실행,35칸/2명 표시를 확인했다.

`scripts/capture_grid_initiative_replay.mjs`는 작업용 로컬HTTP8765/Chromium9223에서 UI를 검사하고 현재 편집/재생 화면을 캡처한다. `actual.png`/`endurance.png`는 초기 고정 실험 화면이며 새 편집 화면은 `editor-*.png`다.
